## Request pipeline (order)

1. Forwarded headers (only if `ForwardedHeaders:Enabled`). Startup **fails** when it is enabled without at least one valid `KnownProxies` address, so forwarded IP/scheme can never be accepted from arbitrary peers.
2. `UseExceptionHandler` → `ClassHubExceptionHandler`: `ClassHubException` → its status, `code` and safe message; `DbUpdateConcurrencyException` → 409 `CONCURRENCY_CONFLICT`; `BadHttpRequestException` → its 4xx; anything else → 500 `INTERNAL_ERROR` with a generic title (details only in the log).
3. `UseStatusCodePages` → empty 4xx/5xx responses (401, 403, unknown routes, malformed JSON) become ProblemDetails. Every ProblemDetails has `code` (default from `ErrorCodes.ForStatus`) and `traceId`.
4. HSTS outside Development/Testing/E2E.
5. `SecurityHeadersMiddleware`: `nosniff`, `Referrer-Policy`, `Cross-Origin-Opener-Policy`, `Permissions-Policy`; CSP `default-src 'none'` + `X-Frame-Options: DENY` for `/api`, `/health`, `/openapi`; same-origin CSP + `SAMEORIGIN` for pages.
6. Serilog request logging (path without query string) with `SensitiveDataRedactionEnricher` (secrets → `***`, emails masked, nested values included).
7. Routing → authentication (cookie `.ClassHub.Auth`, Identity application scheme; 401/403 instead of redirects) → **rate limiter** → authorization. The limiter runs before authorization so rejected requests (401/403, unknown routes) still count against the client's limits.

## Authorization model (deny by default)

- `FallbackPolicy = RequireAuthenticatedUser`. It also applies to requests that match no endpoint, so anonymous callers get 401 for unknown `/api` routes (no route probing).
- **Every endpoint must declare** `.AllowAnonymous()` or `.RequireAuthorization(<named ClassHub policy>)`; `EndpointAuthorizationMetadataTests` fails otherwise. Policies live in `ClassHubPolicies` (more are added with workspaces in R0-P5).

## API conventions

- Modules implement `IModule` and map relative routes; `MapClassHubModules` mounts them under `/api`. Modules are discovered from `ClassHub.Core` (and the host may register more `IModule` services, which tests use for probe endpoints).
- Request validation: FluentValidation validators (auto-registered from Core) + `.WithValidation<TRequest>()` → 400 `VALIDATION_FAILED` with camelCase field paths (`items[0].displayName`).
- CSRF: cookie-authenticated unsafe endpoints use `.RequireAntiforgeryHeader()`. `GET /api/auth/antiforgery` sets only the HttpOnly, SameSite=Strict `.ClassHub.Antiforgery` cookie and returns the request token in the JSON body (`requestToken`) and the `X-XSRF-TOKEN` response header; the SPA keeps it in memory and sends it as `X-XSRF-TOKEN`. **No JavaScript-readable cookie** is used (a CodeQL finding on the first design). Tokens are bound to the user: fetch a new one after sign-in, sign-out or a 401.
- Rate limiting: a **default** fixed-window limit per client IP for every `/api` request (global limiter, `RateLimiting:DefaultPermitLimit`, 300/min), plus stricter named policies endpoints opt into on top (`auth`, `public-form`, `public-read`). Health checks are not limited. Limits are validated on start; rejections are 429 `RATE_LIMITED` + `Retry-After`. In-memory, no Redis.
- JSON request body limit: 1 MB (Kestrel); upload endpoints set their own limits later.

## Accounts and sessions (R0-P4)

- **ASP.NET Core Identity** (`AddIdentityCore<AppUser>` + roles + EF stores + `SignInManager` + token providers) on `ClassHubDbContext` (now an `IdentityDbContext<AppUser, AppRole, Guid>` with `DataProtectionKeys`). `AppUser` lives in `Modules/Identity/Contracts` (other modules reference users) and adds `Status`, `Locale`, `TimeZone`, `CreatedAtUtc`, `LastLoginAtUtc`.
- **Email is unique in the database** (`EmailIndex` on `NormalizedEmail` is unique; Identity's default index is not). A unique-violation race during registration is answered like a known address.
- **Passwords:** Identity's PBKDF2 hasher; minimum 10 characters, no composition rules; `CommonPasswordValidator` rejects common passwords, single-character repeats and passwords containing the email name. Lockout after 5 failures for 15 minutes.
- **No account enumeration:** register, resend confirmation and forgot password always answer `202` with the same message; password rules are checked before the email is looked up; wrong password, unknown email and locked accounts all give `401 INVALID_CREDENTIALS` (unknown emails verify a dummy hash). `403 ACCOUNT_SUSPENDED` only after the correct password.
- **Sessions:** cookie `.ClassHub.Auth` (Identity application scheme): HttpOnly, SameSite=Lax, Secure outside dev, 30-day sliding expiry; persistent only with "remember me". `SecurityStampValidator` re-checks the cookie every `Identity:SecurityStampValidationIntervalSeconds` (60 s, D-51). Password reset and suspension rotate the stamp, so sessions end. `AddIdentityCore` does not register `ISecurityStampValidator` or Identity's companion cookie schemes; both are registered explicitly (the validator otherwise does nothing; sign-out of the missing schemes otherwise throws).
- **Tokens:** email confirmation (24 h, own provider) and password reset (2 h, invalidated by the stamp change) are Data Protection tokens. Data Protection keys live in the database (DPAPI-protected on Windows in Development). Email links carry tokens in the URL **fragment** (`/verify-email#userId=…&token=…`, `/reset-password#email=…&token=…`), which browsers never send to servers.
- **Antiforgery after sign-in/out:** the API sets `HttpContext.User` to the new identity before issuing a new request token (header `X-XSRF-TOKEN`) because tokens are bound to the user.
- **Email outbox:** `IEmailOutbox.Enqueue` adds an `EmailOutbox` row in the same unit of work; `EmailOutboxDispatcher` (`BackgroundService`) claims rows with `UPDATE TOP (n) … WITH (UPDLOCK, READPAST, ROWLOCK)` and a lease, delivers through `IEmailSender`, retries with exponential backoff (max 8 attempts), and clears bodies after delivery. Provider `DevMailbox` (Development/Testing/E2E) stores messages in `DevMailbox`, visible at `GET /api/dev/mailbox` (mapped only in those environments); provider `None` only queues. Resend comes with hosting.
- Emails are localized (mk default, en) in `AccountEmails`; user values are HTML-encoded.

## Workspaces and tenancy (R0-P5)

- `Modules/Workspaces`: `Workspace` (the tenant: name, IANA time zone, ISO 4217 currency, locale, rowversion) and `WorkspaceMember` (`ITenantOwned`; role, revocation; one active membership per user and workspace). `IWorkspaceProvisioning` (Contracts) is called by registration inside its transaction.
- Endpoints: `GET /api/me/workspaces` (`Authenticated`), `GET|PATCH /api/w/{workspaceId}` (`ws:workspace.read` / `ws:workspace.manage`, antiforgery on PATCH).
- `Infrastructure/Tenancy`: `TenantContext`, `WorkspacePermissionHandler` + `WorkspacePolicyProvider` + `WorkspaceAuthorizationResultHandler` (non-member → 404), `TenancyModelConventions` (named `Tenant`/`Archived` filters, `HasTenantReference`), `TenantSaveChangesInterceptor` (added in `ClassHubDbContext.OnConfiguring`). The DbContext receives `ITenantContext` through DI; a context created without one sees no tenant rows.
- `Infrastructure/Audit`: `IAuditLog.Record(...)` adds an `AuditLogEntry` to the caller's unit of work.
- `SharedKernel`: `ITenantOwned`, `IArchivable`, `ITenantContext`, `WorkspaceRole`, `WorkspacePermissions`, `WorkspacePolicies`, `PlatformRoles` (roles seeded with fixed ids).
- `TenancyModelConventions` only touches entities that implement `ITenantOwned`/`IArchivable` (configuring every entity type re-included Identity's passkey data type and broke the model).

Details and tests: [SECURITY.md](SECURITY.md#tenant-isolation-r0-p5).

## Web app and SPA hosting (R0-P6)

- `web/` is one Vite SPA with a React Router data router (`src/app/routes.tsx`) and four area layouts (`src/app/layouts/AppShell.tsx`): teacher `/app`, student `/student`, admin `/admin`, and auth pages. Each layout has a desktop sidebar and a mobile drawer (Radix Dialog).
- UI primitives are shadcn-style components in `src/components/ui` (Tailwind v4 tokens in `src/index.css`, `cn()` in `src/lib/utils.ts`).
- Localization: i18next (`src/i18n`) with `mk` (default) and `en`. The choice is stored in `localStorage` (`classhub.language`) and sets `<html lang>`. `npm run i18n:check` enforces key parity and a translation for every backend error code in `ErrorCodes.cs`.
- Formatting (`src/lib/format.ts`) always takes an IANA time zone and shows money from minor units with its currency.
- API access: `src/api/client.ts` wraps `openapi-fetch` with the generated types. It sends cookies, keeps the antiforgery request token in memory, fetches it from `GET /api/auth/antiforgery` before the first unsafe request, adopts tokens re-issued in the `X-XSRF-TOKEN` response header, retries once on `ANTIFORGERY_INVALID`, and turns ProblemDetails into `ApiError`. `errorMessage()` shows only translated messages for error codes, never server text. TanStack Query is provided in `src/app/Providers.tsx`.
- Hosting: `npm run build` writes to `src/ClassHub.Api/wwwroot/dist` (git-ignored, base `/dist/`). `Platform/SpaHosting.cs` serves static files before routing (hashed `/dist/assets` immutable, everything else `no-cache`) and maps `dist/index.html` as the fallback for the SPA prefixes only (`/` is the Razor landing page since R1-P4; the SPA's `/` route hands over with a full page load). `/api`, health checks and unknown paths never get the SPA, and the deny-by-default policy still applies to them.

## Availability and booking (R2-P6)

- In `Modules/Lessons`: `BookingSettings` (per workspace: on/off, slot step 15/30/60, notice 0–168 h, horizon 7–90 days, version), `WorkingHours` (weekday intervals, local), `TimeOff` (whole local days) and `BookingRequest` (offer as requested, UTC start/end, status Pending/Confirmed/Declined/Cancelled, lesson; composite tenant FKs to `Leads`, `Offers` and `Lessons`).
- **Free slots** (`BookingSlots`): every step within working hours where the whole lesson fits, outside days off, after the notice, within the horizon, minus the teacher's non-cancelled lessons in every workspace (half-open; skipped local times give none). Pending requests do not hold a slot (D-23).
- **Request:** the visitor uses `/{slug}/book` (Razor page, `booking-widget` island; all times state the teacher's zone). The request is a public lead (`LessonRequest`) with `SlotStartUtc`: the lead intake's protection applies unchanged (signed form token, minimum fill time, honeypot, per-site hourly cap under the intake lock, consent, rate limits), and `IBookingIntake` checks the slot and records the booking in the same transaction. The visitor's contact details and consent live on the lead only.
- **Teacher:** `/api/w/{id}/booking/settings` and `/requests` (`/confirm`, `/decline`, `/reschedule`, `/cancel`). Confirming makes the request a student (`ILeadStudents`, the idempotent D-12 conversion), then under the schedule lock re-checks the slot and creates the lesson (409 `LESSON_OVERLAP` leaves it pending); reschedule and cancel act on that lesson. The visitor gets an email for each decision (`booking.*`).
- **Public site:** `IBookingAvailability` adds a "Book a lesson online" link to the site page while booking is on (saving the settings evicts the cached page).
- **SPA:** "Booking" (requests with their actions; working hours, days off and rules).

## Recurring lessons (R2-P5)

- `LessonSeries` (tenant-owned; who/what/where like a lesson, local `StartDate`/`StartTime` in its time zone, duration, every 1 or 2 weeks, ends on a date, after a count or never, `NextIndex`, `ReplacedBySeriesId`, version) and `LessonSeriesSkip` (occurrence index, date, reason). Occurrences are ordinary `Lessons` with `SeriesId`/`SeriesIndex` (unique per series, composite tenant FK) and a `SeriesException` flag.
- **Materializing:** occurrences up to 12 weeks ahead (`SeriesPattern`: same local time across DST; a skipped local time has no instant). Each one is checked for overlaps under the teacher's schedule lock; an overlapping, non-existent or unavailable (archived student/group, empty group) occurrence is skipped and recorded, the rest is created. `LessonSeriesHorizonJob` extends series hourly: per series it binds the series' workspace as its teacher (only while the teacher is an active member) and uses the same service, so tenant filters, the lock and the overlap checks apply as for the teacher.
- **D-24 edits:** "only this lesson" is the lesson editor (it marks the lesson `SeriesException`). "This and following" (from a lesson) and "all future" (from the next one) end the series at an instant (the selected lesson, or now; earlier if the new series starts on an earlier day; never before now; `EndDate` becomes the last local day before it, `ReplacedBySeriesId`), remove its scheduled, unchanged lessons from that instant and its skips from that day, and create a new series with the new settings, all in one transaction (a refused edit changes nothing). Held, cancelled and individually changed lessons are never touched, nor is a lesson that already started. An edit names the zone its times were shown in (the series' own on the series page, the workspace's in the lesson editor), so unchanged times keep their instants. Ending a series removes its upcoming scheduled lessons from a date.
- **API:** `/api/w/{id}/lesson-series` create, get (with skips), update (`ThisAndFollowing`/`AllFuture`), `/end`.
- **SPA:** "Repeat" in the new-lesson editor (weekly / every two weeks; after N lessons, on a date, no end); scope choice on a series lesson; the series page (summary, skipped dates, change all future lessons, end the series; a replaced series links to the one that continues it).

## Lessons and calendar (R2-P4)

- `Modules/Lessons`: `Lesson` (tenant-owned; teacher, individual or group (composite tenant FK to `Groups`), subject, title, topic, UTC start/end plus the IANA time zone it was scheduled in, online link (https only) or location, status, cancellation reason, version) and `LessonParticipant` (composite tenant FKs to `Lessons` and `Students`). A group lesson takes the group's active members when it is scheduled (or when its group changes), so later membership changes do not rewrite the history.
- **Statuses (D-22):** Scheduled → Completed (only once started) or Cancelled (reason required); both are final, and only scheduled lessons can be edited (`LessonRules`).
- **No overlaps:** create and reschedule run in a transaction under `classhub:schedule:{teacherUserId}` (`LessonQueries`), then check the teacher's non-cancelled lessons in half-open intervals (touching lessons are fine); 409 `LESSON_OVERLAP`. The overlap query reads the teacher's own lessons across workspaces (allow-listed) and returns only a yes/no.
- **Time zones:** the client sends a wall-clock `startLocal` and a duration; the server converts with the workspace time zone (`LessonTime`): a time skipped when clocks go forward is refused (400 `startLocal`), a time that occurs twice means the first occurrence. The calendar reads by local days (`from`/`to`, at most 62 days); responses carry both UTC and local times.
- **API:** `/api/w/{id}/lessons` list (by days, optional student/group), get, create, update (version), `/complete`, `/cancel`; permissions `lessons.read` / `lessons.manage`.
- **SPA:** "Calendar" (day/week/month, Monday-first weeks, today in the workspace time zone; the week is an agenda on phones and the month shows counts) and the lesson editor (student picker with search and paging, group, subject, date, time, duration, online/in person; held/cancel actions). Entity editors are keyed by the route id, so opening a new entity (also right after creating one) waits for its fresh load.

## Student accounts (R2-P3)

- **Invitations:** `StudentInvitation` (tenant-owned; only the SHA-256 hash of a 32-byte random token is stored, 7 days, single use, at most 5 per student per day). The link is `/student/invitation#token=…` (fragment: never in server logs). A new invitation, archiving the student or unlinking revokes pending ones.
- **Accepting** (`/api/student-invitations/*`, the token is the capability): `preview` (anonymous), `accept` (signed in: links that account) and `accept-with-account` (creates an account for the invited email through `IInvitedAccounts` in the Identity module: confirmed email, no teacher workspace, then signs in). Everything runs in one transaction under the workspace's student-intake lock; `Students.UserId` has a filtered unique index per workspace (one account, one student record per teacher; several teachers allowed, D-16). The cross-tenant reads (by token hash or by the signed-in user's id) live in the allow-listed `StudentAccountQueries`.
- **Minors (D-18, provisional):** accepting for a student marked as a minor requires confirming a parent's or guardian's agreement; the time is recorded on the invitation.
- **`student:self` policy:** `/api/student/w/{workspaceId}/…` requires an active (not archived) student record of the user in that workspace (`StudentSelfHandler` + `IStudentSelfLookup`); it binds the request to that record (`ITenantContext.StudentId`), so tenant filters apply and data is always derived from the session. Everyone else gets 404. `/api/student/teachers` lists the user's teachers.
- **Teacher side:** `POST/DELETE /api/w/{id}/students/{studentId}/invitation`, `DELETE …/account` (unlink; the account stays). `StudentResponse` shows `AccountLinked` and the pending invitation, never the account's credentials.
- **SPA:** account card on the student page; `/student/invitation` (create an account, or sign in and come back: the token is kept in `sessionStorage` for the tab); the student portal (`/student`: teachers, `/student/w/:id`: own page, `/student/settings`: language, notifications placeholder). An account without a workspace is sent from `/app` to `/student`.

## Groups (R2-P2)

- `Modules/Groups`: `Group` (tenant-owned, archivable; name, optional catalog subject, description, version) and `GroupMember` (key `(GroupId, StudentId)`; composite tenant FKs to `Groups` and `Students`, so a member is always a student of the same workspace). A student can be in several groups.
- **History kept:** removing a member sets `RemovedAtUtc` (re-adding reopens the row); archiving keeps the members. Later lessons and attendance (R2-P4/P5) reference these rows.
- **Members lock:** adding or removing members and archiving/restoring run in a transaction under `classhub:group-members:{group}` (`GroupQueries`), so the 100-member cap and "no new members in an archived group" hold under parallel requests. Member changes do not move the group's version, so an open details editor is not invalidated by them. Students are read through `IStudentLookup` (Students contract); archived students cannot be added.
- **API:** `/api/w/{id}/groups` list (active or archived, optional `studentId`), get, create, update (version), archive/restore, `POST /members`, `DELETE /members/{studentId}`; permissions `groups.read` / `groups.manage`.
- **SPA:** "Groups" in the teacher area (list, create/edit, member list with search-and-add, remove, archive/restore); a "Groups" card on the student page.

## Students (R2-P1)

- `Modules/Students`: `Student` (tenant-owned, archivable; first/last name, email lowercase and unique per workspace via a filtered unique index, phone, minor flag with guardian name/email/phone (D-18), source lead), `StudentSubject` and `StudentNote` (private notes; composite tenant FKs). A student exists without a login (accounts with invitations, R2-P3).
- **Intake lock:** every creation (manual add, lead conversion, restore) and every email change runs in a transaction under `classhub:student-intake:{workspace}` (`StudentQueries`), so the email dedupe and the Free active-student limit (`IEntitlementService`, `active-students`) hold under parallel requests; the unique index backs the dedupe in the database.
- **Lead conversion (D-12):** `POST /api/w/{id}/students/from-lead` through `ILeadConversion` (Leads module): idempotent (an already converted request returns its student), links to the student with the same email (archived ones included) or creates one from the request (name split, email, phone, subject), and marks the request `Converted` with `Leads.StudentId` (composite tenant FK to the student).
- **API:** list (active or archived, search by name/email/phone/guardian, active count), get, create, update (version), archive/restore, notes (list/add). Notes are never part of a student response (architecture test `StudentPrivacyTests`). Deactivated catalog subjects stay valid on students that already have them.
- **SPA:** "Students" in the teacher area (list, add/edit with guardian fields for minors, subjects, archive/restore, private notes); "Make a student" on the request page.
- **Logging:** student and guardian names and phones are redacted like credentials (`SensitiveDataRedactionEnricher`).

## Moderation & reference data admin (R1-P11)

- **Hidden flags live with the content:** `Site.HiddenAtUtc`/`HiddenReason` (whole site), `Site.HiddenSectionsJson` (section types with reason and time), `DiagnosticTest.HiddenAtUtc`/`HiddenReason`. The public queries themselves exclude them (`PublicSiteQueries.Published()`, the public test queries, `TestAttemptQueries`), so the page, photo, sitemap, lead form, test pages, attempts and test links all inherit it; hidden sections are stripped from the snapshot before rendering. Publishing never touches these flags.
- **`Modules/Moderation`:** `AbuseReport` (platform data, not tenant-owned: target site/section/test, reason, optional details and reporter email, status). `POST /api/public/sites/{slug}/reports` (anonymous, `public-form` limiter, honeypot, at most 20 stored per site per hour; only content a visitor can see now). Staff queue `/api/admin/reports` (list, detail, hide with a reason, dismiss), `/api/admin/moderation/hidden` and `/restore`. Hide/restore run in one transaction through `ISiteModeration` / `ITestModeration` (allow-listed `*ModerationQueries`), are audited, email the teacher (`moderation.hidden` / `moderation.restored`, never the reporter's details) and evict the public pages after the commit. Hiding resolves every open report about the same content. Decisions about one piece of content (hide, dismiss) take a lock per content and reports carry a version, so parallel decisions cannot overwrite each other (the second gets 409); site and test moderation changes are serialized per content, and report intake counts and inserts under a lock per site (the hourly cap holds under parallel reports).
- **Catalog admin:** `/api/admin/catalog` (staff): create (permanent code), rename, reorder, (de)activate categories, subjects and levels; audited; never deleted. The teacher catalog and the reference checks offer only active entries (subjects also need an active category); existing references stay in the database, and the profile form drops deactivated ones on its next save.
- **SPA:** the `report-abuse` island in the footer of site and test pages; admin pages for reports, hidden content and the catalog; teacher notices in the site and test editors (with the reason) and a "hidden" badge in the test list.

## SaaS plans & entitlements (R1-P10)

- `Modules/Subscriptions`: `Plan` + `PlanLimit` (platform reference data, seeded Free/Pro with the provisional D-29 values), `WorkspaceSubscription` (one row per workspace once it ever had Pro; tenant-owned) and the append-only `SubscriptionEvent` history (Activated / Extended / Expired, with the manual payment record of each activation, D-30).
- **Effective plan:** a workspace is on the default plan (Free) unless its paid period has not ended (`SubscriptionPeriods`); the limits follow the end date on every request. `SubscriptionExpiryJob` (`BackgroundService`, `Subscriptions:ExpiryCheckSeconds`) moves ended periods back to Free and records it (history dated at the end of the period, audit, no actor); a staff activation first records a period that ended but was not processed yet, so no expiry is lost. Nothing is deleted or hidden (D-29b).
- **`IEntitlementService.EnsureWithinLimitAsync`:** inside the caller's transaction, an application lock per workspace and limit, then the count and the comparison; 422 `PLAN_LIMIT_REACHED` when exceeded. Used by publishing a diagnostic test (count + publish + commit under the lock, eviction after the commit), replacing the R1-P6 placeholder hook. Active students (R2-P1), activities and storage are enforced when their features arrive; analytics level 1/2 is exposed for the advanced reports.
- **API:** teacher `GET /api/w/{id}/plan` (limits and usage, no way to change it); staff `GET /api/admin/plans`, `PUT /api/admin/plans/{code}` (owner only, every limit, version check, audited), `GET /api/admin/workspaces/{id}/subscription`, `POST /api/admin/workspaces/{id}/subscription/pro` (activate or extend from the end of an active period; applock per workspace; history + audit). The admin overview adds Pro workspaces and the payments of the last 30 days per currency.
- **SPA:** teacher "Plan" page (limits, usage, how to get Pro); admin plans page (editable for the owner) and a plan card on the user page (state, history with payments, activation form).

## Platform administration (R1-P9)

- **MFA** (`Modules/Identity`): `MfaService` (status, key setup, enable with the first code, recovery codes, `IMfaStepUp` for critical operations) under `/api/auth/mfa`; two-step sign-in (`/api/auth/login` answers 202 when the authenticator is on, `/api/auth/login/two-factor` finishes). `ProtectedUserStore` encrypts the authenticator key and recovery codes with Data Protection. `IUserAccountStatus` suspends/reactivates with a reason (transaction with the stamp rotation and the audit entry; eviction of public pages after the commit).
- **Policies:** `platform:staff` / `platform:owner` (`PlatformStaffRequirement`: role + `amr=mfa`; a missing MFA session is 403 `MFA_REQUIRED`). `OnRefreshingPrincipal` copies `amr` into the refreshed principal. Staff cookies: session-only, 8 h sliding (`OnSigningIn`).
- **`Modules/Admin`** (`/api/admin`, `platform:staff`): overview (users, suspended, teachers = owners of a workspace, active teachers = not suspended and signed in during the last 30 days, registrations in 7/30 days, published sites, staff), user search (email/id, status, staff; 20 per page), user detail with the audit entries about the account, suspend/reactivate (reason 3–500 chars), Platform Admin grant/revoke (`platform:owner` + step-up code), audit viewer (action prefix, user as actor or target, workspace, UTC days). Cross-tenant metadata comes from `IWorkspaceDirectory` and `ISiteDirectory` (allow-listed `*Queries` files); no workspace content.
- **SPA** `/admin`: `AdminGate` (no access for non-staff; authenticator enrollment with a QR code (`uqr`) and the key as text; recovery codes shown once; "sign in again" for password-only sessions), overview, users, user detail, audit log, security (new recovery codes). The login page has the second step (code or recovery code). Staff see an area switch in the header.

## Teacher dashboard (R1-P8)

- `Modules/Dashboard`: `GET /api/w/{id}/dashboard?days=7|30|90` (`ws:workspace.read`; other periods → 400). The period is whole UTC days ending today, like the page-view counter. Numbers come from the other modules' contracts, all tenant-filtered (own metrics only): `ILeadStats` (new and by status now, without the archive; arrivals by type in the period, archived included), `ITestStats` (published tests, attempts and shared results in the period), `ISiteStatus` + `ISitePageViewStats` (visits per day, zeros filled in), `IOfferLookup.CountActiveAsync` (active / on the public site), `IOnboardingProgress`.
- **Definitions (ROADMAP J.3 item 12):** a *page visit* is one counted view (D-32: anonymous browser GETs of the published page, no bots, prefetches or signed-in users); a *conversion* is a lead whose status is Converted (the conversion into a student record comes with R2-P1). The funnel shows visits → requests that arrived → of those contacted (Contacted or Converted) → converted.
- SPA: the workspace home shows the period switch, stat tiles (new requests link to the filtered inbox), the funnel with each step's share of the one before, requests by status (links to the inbox) and daily visits (single-series bar chart with per-day tooltip, a text summary and a table view), above the onboarding checklist.

## Public test taking & results (R1-P7)

- **Public API** (`/api/public/sites/{slug:siteslug}/tests/{testSlug:testslug}`, anonymous): `GET` (`no-store`) → `PublicTestResponse` (questions and options, `SelectSeveral` for checkbox questions, **no correct answers**); `POST /attempts` (rate limit `public-form` per IP, plus an atomic hourly cap per test `DiagnosticTests:MaxAttemptsPerTestPerHour`, default 200, under `sp_getapplock`) → choices validated against the test (only its questions and their options, each once; otherwise 400 and nothing stored), scored by `TestScoring`, stored as an anonymous `TestAttempt` (random v4 id, answers JSON, score; no name, email, IP or agent) and counted on the test (`AttemptCount`, which locks destructive edits, D-38). The answer is totals only.
- **Contact with the result:** the lead intake accepts `type: Diagnostic` with the `attemptId` (and an opt-in `shareResult`, D-18): the attempt must belong to this site's workspace and have no lead yet (one request per attempt, unique indexes on both sides); the lead and the attempt link are written in the same transaction. The teacher sees the score only when it was shared.
- **Pages:** Razor `/{slug}/tests/{testSlug}` (indexable intro: title, subject, difficulty, questions, points, privacy note; canonical; output-cached per site and test, evicted on test changes), the site page lists published tests, the sitemap includes them; island `diagnostic-test` runs the test and then shows the contact form in "test result" mode.
- **Teacher:** `GET /api/w/{id}/tests/{testId}/attempts` (count, shared results with the lead link); the lead detail shows the test and, if shared, the score. `IPublicTests` (published tests, no Sites dependency) and `IDiagnosticAttemptLink` (used by the lead intake) are the cross-module contracts.

## Diagnostic test builder (R1-P6)

- `Modules/DiagnosticTests`: `DiagnosticTest` (`ITenantOwned`, `IArchivable`): title, slug (unique per workspace, archived tests keep theirs; generated from the title with `Slugs.FromText` and a free `-2`, `-3` … suffix), subject, description, difficulty, status (Draft / Published / Inactive), `AttemptCount` (written by R1-P7), `Version`. `TestQuestion` (position, text, points 0–100) and `TestOption` (position, text, `IsCorrect`), both with composite tenant FKs.
- Endpoints `/api/w/{id}/tests` (`ws:tests.read` / `ws:tests.manage`): list, create, get (with correct options — teacher only), `PUT` (the whole test at once; questions and options keep their ids, ids of other tests or workspaces are refused), `publish` (readiness: a question worth points, at least two options and a correct one per question; 400 lists the problems; `IPublishedTestQuota` hook for the plans in R1-P10), `deactivate`, `duplicate`, `DELETE` (archive).
- **D-38:** with attempts, only texts, title, description, difficulty, address and order may change; structure, correct answers, points and subject → 409 `TEST_HAS_ATTEMPTS`; "duplicate" creates an editable draft with new ids.
- `TestScoring.Score`: server-side, all-or-nothing per question (exactly the correct options), unknown answers ignored — used by public test taking (R1-P7).
- Architecture test `PublicProjectionTests`: nothing reachable from a public projection (`Public*` types, the site render model, the lead form) has answer-revealing members or domain entities.
- SPA: `/app/w/{id}/tests` (list), `/tests/new` and `/tests/{testId}` (editor with questions, options, correct answers, points, status, duplicate, archive; structure locked when there are attempts); nav "Tests".

## Leads (R1-P5)

- `Modules/Leads`: `Lead` (`ITenantOwned`, `IArchivable`): type (`Message` / `LessonRequest`, no slot until R2-P6, D-13), status (New → Contacted → Converted / Closed; `LeadStatusRules`), name, email, phone, message, offer (composite tenant FK + title snapshot), subject, consent version and time (D-18), `Version`. `LeadNote` (private notes, composite FK to the lead).
- **Public intake** (`/api/public/sites/{slug:siteslug}`, anonymous, no antiforgery, no cookies used): `GET /lead-form` (`no-store`): availability, a signed **form token** (Data Protection, site + load time), the requestable offers (public, active), the teacher's subjects, the versioned consent and minors notice in the site language. `POST /leads` (rate limit `public-form` per IP): always `202 {received: true}`, nothing echoed. Spam (D-19): honeypot `website` and submissions faster than `Leads:MinimumFillSeconds` (default 3) are dropped silently; expired/foreign tokens → 422 `FORM_EXPIRED`; per-site limit `Leads:MaxPerSitePerHour` (default 20) → 429. Checks run under the **read-only** public tenant binding; the lead and the teacher's email are written in a separate scope with the workspace set explicitly.
- **D-10b:** publishing a site and receiving leads need a confirmed owner email (`IWorkspaceOwnerContact`): 422 `EMAIL_NOT_CONFIRMED` / `LEADS_UNAVAILABLE`, the form is hidden.
- **Teacher email** (`leads.new`, outbox): only the kind of request and a link to the inbox, never the visitor's data.
- **Inbox** (`/api/w/{id}/leads`, `ws:leads.read` / `ws:leads.manage`): list (status, type, text search on name/email/message, archived, paging ≤ 50, `newCount`), detail with notes, `PUT /status` (version, 422 `INVALID_STATUS_TRANSITION`), `POST /notes`, `POST /archive` / `/restore`.
- **Island** `contact-form` in the Contact section of the public page (not the preview); SPA pages `/app/w/{id}/leads` and `/leads/{leadId}`, nav "Requests".

## Public sites: rendering, SEO, cache and islands (R1-P4)

- **Publishing** (`POST /api/w/{id}/site/publish` / `unpublish`, `ws:site.manage`, version-checked, audited `site.published` / `site.unpublished`): the saved draft's template, palette, language and sections are frozen into `PublishedJson` (`SiteSnapshot`). The slug is the address and applies at once; profile data (name, photo, subjects, levels, languages, teaching mode) and the offers marked "show on public site" (active, not archived) stay live. `SiteResponse` reports `publishedAtUtc`, `hasUnpublishedChanges` and `viewsLast30Days`; the onboarding step "publish" is available and follows the site.
- **Routing** (`src/ClassHub.Api/Pages`): `Public/Landing` at `/` and `/en`, `Public/Site` at `/{slug:siteslug}` (route constraint `SiteSlugRouteConstraint`: only valid, non-reserved slugs, so app areas never match), `Preview` at `/preview/{token}`. Root endpoints (`Platform/PublicSiteEndpoints.cs`): `/{slug}/photo`, `/preview/{token}/photo`, `/sitemap.xml`, `/robots.txt`.
- **Read side:** `IPublicSites` (Sites) → `PublicSiteQueries` (allow-listed cross-workspace lookup: published sites only, the single place where moderation's "hidden" condition goes in R1-P11) → `IWorkspacePublicVisibility` (Workspaces: owner membership active and owner account not suspended) → only then `TenantContext.SetPublicReadOnly(workspaceId)`: the normal tenant filters serve the profile (`ITeacherPublicProfile`) and offers (`IOfferLookup.ListPublicAsync`), and the save interceptor refuses **every** tenant-owned write in such a request.
- **One renderer:** `SiteRenderer` builds a `SiteRenderModel` (the allow-list of what a template may show: visible sections only, public profile fields, public offers with prices in major units via `Currencies.MinorDigits`, the same table as the SPA's Intl) for both the public page and the preview; `Pages/Shared/_SiteBody.cshtml` renders the three templates with Tailwind classes and palette classes (`palette-*`), no inline styles.
- **SEO** (`SiteSeo`): title, description (≤ 160, word boundary), canonical and Open Graph/Twitter tags with absolute URLs from `App:PublicBaseUrl` (never the Host header), `og:image` only when the hero shows the photo, JSON-LD `@graph` with `Person` (+ `makesOffer` / `Offer` / `Service`) and `FAQPage`. Unknown, unpublished or hidden sites: 404 page with `noindex` (meta + header). Landing page: canonical + `hreflang` mk/en/x-default. Sitemap: landing pages and visible published sites with `lastmod`; robots: `Disallow` for app areas as `/area/` + `/area$` (a plain prefix would block sites such as `/applied-math`).
- **Output cache** (in-memory, policies in `SitesModule`): site pages 5 min, landing/robots/sitemap 1 h; only anonymous GET 200 responses without cookies are stored (default policy rules), arbitrary query strings share one entry. Site pages are tagged `public-site:{workspaceId}` (added by the page handler) and `public-sites`; `IPublicSiteCache` evicts after commits that show on the page: site publish/unpublish/slug change, profile and photo changes, offer create/update/archive/reorder; account suspension/reactivation evicts all site pages and the sitemap. The browser gets `Cache-Control: no-cache`.
- **Page views** (D-32): `SitePageViewMiddleware` runs before the output cache (so cached hits count) and adds one view per site and UTC day (`SitePageViews`, atomic `MERGE … HOLDLOCK`) for GET 200 responses of anonymous requests with a browser-like user agent, not prefetches. No cookies, IPs, agents or per-visit rows.
- **Vite islands:** Vite builds the SPA, `src/public/public.css` (Tailwind v4 scanning only `src/ClassHub.Api/Pages` and `web/src/islands`, palette classes) and every `src/islands/*.tsx` as entries into one manifest. `ViteManifest` (re-read when the file changes) resolves entries; tag helpers `<vite-asset entry="…">` (stylesheet/script tags) and `<vite-island name="…" props="…">` (mount element with JSON props in `data-props`, plus the island's files, each once per response). `islands/mount.tsx` mounts an island into every matching element. First island: `copy-link` in the public site footer. Without a build the pages render unstyled (warning logged once).

## Public site model, editor and preview (R1-P3)

- `Modules/Sites`: `Site` (one per workspace, `ITenantOwned`): slug (platform-unique, `SiteSlugs` rules + reserved words incl. every SPA prefix, binary collation, unique index), template (`classic`/`modern`/`minimal`), palette (`SitePalettes`, WCAG AA tested), language (D-15), `DraftJson` / `PublishedJson` (ISJSON checks), `Version`.
- Content = `SiteContent`: the eight section types (hero, about, subjects, experience, offers, testimonials, faq, contact), each exactly once, in display order, shown or hidden; structured plain text only (titles, texts, items), normalized and length-limited. Subjects and offers are filled from the profile and the offers marked "show on public site" when rendering (R1-P4).
- Endpoints `/api/w/{workspaceId}/site` (`ws:site.read` / `ws:site.manage`): `GET` (draft, or suggestions with `exists = false`; slug suggested from the teacher's name with Cyrillic transliteration), `PUT` (save draft; version; a slug collision is decided by the unique index → 409 `SLUG_TAKEN`), `GET /slug-availability` (allow-listed cross-workspace yes/no query), `POST /preview`.
- Preview: `SitePreviewTokens` (Data Protection, purpose `ClassHub.Sites.Preview.v1`, 15 minutes, site + workspace + member) → Razor page `/preview/{token}` (`src/ClassHub.Api/Pages`, `AddRazorPages`): the member must still be active, then the request is bound to that workspace and the normal tenant filters apply. `noindex` (meta + `X-Robots-Tag`), `no-store`, `no-referrer`; the SPA shows it in a sandboxed iframe (`allow-same-origin`, no scripts).
- Contracts used: `ITeacherSummary` (Teachers: name, photo), `IWorkspaceSettings.GetLocaleAsync`; Sites offers `ISiteStatus` (onboarding "prepare your public page") as a separate dependency-free class to avoid a service cycle with the teacher profile.
- SPA: `/app/w/{id}/site` (address with live availability, template, palette, language, sections with show/hide, reorder, item lists; save draft; preview).

## Offers & programs (R1-P2)

- `Modules/Offers`: `Offer` (`ITenantOwned`, `IArchivable`): kind (single lesson / package / group program), title, description, subject (catalog FK), duration, price in **minor units** with an ISO 4217 currency (default: the workspace currency), mode, lesson count (packages only), seats (group programs only), active, show on public site, display order, `Version` (optimistic concurrency).

- Endpoints under `/api/w/{workspaceId}/offers` (`ws:offers.read` / `ws:offers.manage`): list, create, get, update (version required, stale → 409), archive (`DELETE`: hidden, never bookable, history kept), `PUT /order` (complete list).

- SPA: `/app/w/{id}/offers` (list, reorder, archive with confirmation) and `/offers/new`, `/offers/{offerId}` (form; prices typed in major units and converted with `parseMoney`).

## Auth UI and session (R0-P7)

- Screens (`src/app/pages/auth`): sign in, register, verify email, forgot and reset password, with React Hook Form + Zod (`src/auth/schemas.ts` mirrors the API rules; the API stays authoritative). Field errors from the API are shown as translated messages, never as server text.
- Session (`src/auth/session.ts`): `useMe()` (`GET /api/auth/me`, `null` on 401), sign-in/sign-out mutations that clear the query cache, and the account language: after sign-in the account's language wins; switching language while signed in saves it with `PATCH /api/auth/me` (`locale`, `timeZone`).
- `RequireAuth` guards `/app`, `/student` and `/admin` (UX only) and sends visitors to `/login?returnTo=…`; `safeReturnTo` accepts only same-site paths (no open redirect).
- Teacher area: `/app` opens `/app/w/{workspaceId}`; a workspace the user is not a member of shows "not found" (the API answers 404). The header shows the account and sign-out; unconfirmed accounts see a banner with "send again".
- Tokens from email links are read from the URL fragment once and removed from the address bar.
- OpenAPI: `RouteParameterOperationTransformer` documents route parameters that handlers do not bind (workspace routes), so the generated client can fill them.

## Principles (from ROADMAP)

- **Modular monolith:** `ClassHub.Api` is only the composition root. Business modules live in `ClassHub.Core/Modules/<Name>/` and implement `IModule`. A module may use another module only through its `Contracts` namespace (enforced by architecture tests from R0-P3).
- **Single origin:** `/api/*` (REST), SPA routes (`/app`, `/student`, `/admin`, auth pages) and Razor public pages (`/`, `/{slug}`, …) are all served by one ASP.NET Core app (from R0-P6 / R1-P4).
- **Tenant isolation:** each teacher's workspace is the tenant boundary; layered isolation per ROADMAP C.7 (from R0-P5).
- **Contracts:** the OpenAPI document is generated at build time and turned into TypeScript types for the SPA (from R0-P3).
