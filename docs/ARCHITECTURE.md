## Request pipeline (order)

1. Forwarded headers (only if `ForwardedHeaders:Enabled`). Startup **fails** when it is enabled without at least one valid `KnownProxies` address, so forwarded IP/scheme can never be accepted from arbitrary peers.
2. `UseExceptionHandler` → `ClassHubExceptionHandler`: `ClassHubException` → its status, `code` and safe message; `DbUpdateConcurrencyException` → 409 `CONCURRENCY_CONFLICT`; `BadHttpRequestException` → its 4xx; anything else → 500 `INTERNAL_ERROR` with a generic title (details only in the log).
3. `UseStatusCodePages` → empty 4xx/5xx responses (401, 403, unknown routes, malformed JSON) become ProblemDetails. Every ProblemDetails has `code` (default from `ErrorCodes.ForStatus`) and `traceId`.
4. HSTS outside Development/Testing/E2E.
5. `SecurityHeadersMiddleware`: `nosniff`, `Referrer-Policy`, `Cross-Origin-Opener-Policy`, `Permissions-Policy`; CSP `default-src 'none'` + `X-Frame-Options: DENY` for `/api`, `/health`, `/openapi`; same-origin CSP + `SAMEORIGIN` for pages.
6. Serilog request logging (path without query string) with `SensitiveDataRedactionEnricher` (secrets → `***`, emails masked, nested values included).
7. Routing → authentication (cookie `.ClassHub.Auth`, Identity application scheme; 401/403 instead of redirects) → **rate limiter** → authorization. The limiter runs before authorization so rejected requests (401/403, unknown routes) still count against the client's limits.

## Authorization model (deny by default)

- `FallbackPolicy = RequireAuthenticatedUser`. It also applies to requests that match no endpoint, so anonymous callers get 401 for unknown `/api` routes (no route probing).
- **Every endpoint must declare** `.AllowAnonymous()` or `.RequireAuthorization(<named ClassHub policy>)`; `EndpointAuthorizationMetadataTests` fails otherwise. Policies live in `ClassHubPolicies` (more are added with workspaces in R0-P5).

## API conventions

- Modules implement `IModule` and map relative routes; `MapClassHubModules` mounts them under `/api`. Modules are discovered from `ClassHub.Core` (and the host may register more `IModule` services, which tests use for probe endpoints).
- Request validation: FluentValidation validators (auto-registered from Core) + `.WithValidation<TRequest>()` → 400 `VALIDATION_FAILED` with camelCase field paths (`items[0].displayName`).
- CSRF: cookie-authenticated unsafe endpoints use `.RequireAntiforgeryHeader()`. `GET /api/auth/antiforgery` sets only the HttpOnly, SameSite=Strict `.ClassHub.Antiforgery` cookie and returns the request token in the JSON body (`requestToken`) and the `X-XSRF-TOKEN` response header; the SPA keeps it in memory and sends it as `X-XSRF-TOKEN`. **No JavaScript-readable cookie** is used (a CodeQL finding on the first design). Tokens are bound to the user: fetch a new one after sign-in, sign-out or a 401.
- Rate limiting: a **default** fixed-window limit per client IP for every `/api` request (global limiter, `RateLimiting:DefaultPermitLimit`, 300/min), plus stricter named policies endpoints opt into on top (`auth`, `public-form`, `public-read`). Health checks are not limited. Limits are validated on start; rejections are 429 `RATE_LIMITED` + `Retry-After`. In-memory, no Redis.
- JSON request body limit: 1 MB (Kestrel); upload endpoints set their own limits later.

## Accounts and sessions (R0-P4)

- **ASP.NET Core Identity** (`AddIdentityCore<AppUser>` + roles + EF stores + `SignInManager` + token providers) on `ClassHubDbContext` (now an `IdentityDbContext<AppUser, AppRole, Guid>` with `DataProtectionKeys`). `AppUser` lives in `Modules/Identity/Contracts` (other modules reference users) and adds `Status`, `Locale`, `TimeZone`, `CreatedAtUtc`, `LastLoginAtUtc`.
- **Email is unique in the database** (`EmailIndex` on `NormalizedEmail` is unique; Identity's default index is not). A unique-violation race during registration is answered like a known address.
- **Passwords:** Identity's PBKDF2 hasher; minimum 10 characters, no composition rules; `CommonPasswordValidator` rejects common passwords, single-character repeats and passwords containing the email name. Lockout after 5 failures for 15 minutes.
- **No account enumeration:** register, resend confirmation and forgot password always answer `202` with the same message; password rules are checked before the email is looked up; wrong password, unknown email and locked accounts all give `401 INVALID_CREDENTIALS` (unknown emails verify a dummy hash). `403 ACCOUNT_SUSPENDED` only after the correct password.
- **Sessions:** cookie `.ClassHub.Auth` (Identity application scheme): HttpOnly, SameSite=Lax, Secure outside dev, 30-day sliding expiry; persistent only with "remember me". `SecurityStampValidator` re-checks the cookie every `Identity:SecurityStampValidationIntervalSeconds` (60 s, D-51). Password reset and suspension rotate the stamp, so sessions end. `AddIdentityCore` does not register `ISecurityStampValidator` or Identity's companion cookie schemes; both are registered explicitly (the validator otherwise does nothing; sign-out of the missing schemes otherwise throws).
- **Tokens:** email confirmation (24 h, own provider) and password reset (2 h, invalidated by the stamp change) are Data Protection tokens. Data Protection keys live in the database (DPAPI-protected on Windows in Development). Email links carry tokens in the URL **fragment** (`/verify-email#userId=…&token=…`, `/reset-password#email=…&token=…`), which browsers never send to servers.
- **Antiforgery after sign-in/out:** the API sets `HttpContext.User` to the new identity before issuing a new request token (header `X-XSRF-TOKEN`) because tokens are bound to the user.
- **Email outbox:** `IEmailOutbox.Enqueue` adds an `EmailOutbox` row in the same unit of work; `EmailOutboxDispatcher` (`BackgroundService`) claims rows with `UPDATE TOP (n) … WITH (UPDLOCK, READPAST, ROWLOCK)` and a lease, delivers through `IEmailSender`, retries with exponential backoff (max 8 attempts), and clears bodies after delivery. Provider `DevMailbox` (Development/Testing/E2E) stores messages in `DevMailbox`, visible at `GET /api/dev/mailbox` (mapped only in those environments); provider `None` only queues. Resend comes with hosting.
- Emails are localized (mk default, en) in `AccountEmails`; user values are HTML-encoded.

## Workspaces and tenancy (R0-P5)

- `Modules/Workspaces`: `Workspace` (the tenant: name, IANA time zone, ISO 4217 currency, locale, rowversion) and `WorkspaceMember` (`ITenantOwned`; role, revocation; one active membership per user and workspace). `IWorkspaceProvisioning` (Contracts) is called by registration inside its transaction.
- Endpoints: `GET /api/me/workspaces` (`Authenticated`), `GET|PATCH /api/w/{workspaceId}` (`ws:workspace.read` / `ws:workspace.manage`, antiforgery on PATCH).
- `Infrastructure/Tenancy`: `TenantContext`, `WorkspacePermissionHandler` + `WorkspacePolicyProvider` + `WorkspaceAuthorizationResultHandler` (non-member → 404), `TenancyModelConventions` (named `Tenant`/`Archived` filters, `HasTenantReference`), `TenantSaveChangesInterceptor` (added in `ClassHubDbContext.OnConfiguring`). The DbContext receives `ITenantContext` through DI; a context created without one sees no tenant rows.
- `Infrastructure/Audit`: `IAuditLog.Record(...)` adds an `AuditLogEntry` to the caller's unit of work.
- `SharedKernel`: `ITenantOwned`, `IArchivable`, `ITenantContext`, `WorkspaceRole`, `WorkspacePermissions`, `WorkspacePolicies`, `PlatformRoles` (roles seeded with fixed ids).
- `TenancyModelConventions` only touches entities that implement `ITenantOwned`/`IArchivable` (configuring every entity type re-included Identity's passkey data type and broke the model).

Details and tests: [SECURITY.md](SECURITY.md#tenant-isolation-r0-p5).

## Web app and SPA hosting (R0-P6)

- `web/` is one Vite SPA with a React Router data router (`src/app/routes.tsx`) and four area layouts (`src/app/layouts/AppShell.tsx`): teacher `/app`, student `/student`, admin `/admin`, and auth pages. Each layout has a desktop sidebar and a mobile drawer (Radix Dialog).
- UI primitives are shadcn-style components in `src/components/ui` (Tailwind v4 tokens in `src/index.css`, `cn()` in `src/lib/utils.ts`).
- Localization: i18next (`src/i18n`) with `mk` (default) and `en`. The choice is stored in `localStorage` (`classhub.language`) and sets `<html lang>`. `npm run i18n:check` enforces key parity and a translation for every backend error code in `ErrorCodes.cs`.
- Formatting (`src/lib/format.ts`) always takes an IANA time zone and shows money from minor units with its currency.
- API access: `src/api/client.ts` wraps `openapi-fetch` with the generated types. It sends cookies, keeps the antiforgery request token in memory, fetches it from `GET /api/auth/antiforgery` before the first unsafe request, adopts tokens re-issued in the `X-XSRF-TOKEN` response header, retries once on `ANTIFORGERY_INVALID`, and turns ProblemDetails into `ApiError`. `errorMessage()` shows only translated messages for error codes, never server text. TanStack Query is provided in `src/app/Providers.tsx`.
- Hosting: `npm run build` writes to `src/ClassHub.Api/wwwroot/dist` (git-ignored, base `/dist/`). `Platform/SpaHosting.cs` serves static files before routing (hashed `/dist/assets` immutable, everything else `no-cache`) and maps `dist/index.html` as the fallback for `/` and the SPA prefixes only. `/api`, health checks and unknown paths never get the SPA, and the deny-by-default policy still applies to them.

## Teacher profile, catalog and files (R1-P1)

- `Modules/Catalog`: platform reference data (not tenant-owned): `SubjectCategory`, `Subject`, `EducationLevel` seeded in the migration with deterministic ids (from their codes), mk/en names; teaching languages (ISO 639-1 list in Contracts); `GET /api/catalog` (also the ISO 3166 country codes). Admin editing comes in R1-P11.
- `Modules/Teachers`: `TeacherProfile` (one per workspace: names, bio, teaching mode, country, photo) with `TeacherProfileSubject`/`Level`/`Language` lists, all `ITenantOwned` with composite tenant FKs. Endpoints under `/api/w/{workspaceId}`: `GET|PUT /profile` (`ws:profile.read` / `ws:profile.manage`), `PUT|DELETE|GET /profile/photo`, `GET /onboarding`. Time zone and currency stay workspace settings (`PATCH /api/w/{id}`, audited); the profile screen edits both.
- Cross-module database foreign keys go through Contracts: `CatalogForeignKeyTargets` / `WorkspaceForeignKeyTargets` expose the entity **types** (EF `HasOne(Type)`), so Teachers has no compile-time dependency on another module's domain.
- `Infrastructure/Files`: `IFileStorage` with `LocalDiskFileStorage` (`Files:RootPath`, default `App_Data/uploads` under the content root; outside wwwroot; keys are generated, traversal-checked, never overwritten), `StoredFile` (tenant-owned metadata: purpose, content type, size, SHA-256, dimensions), `ImageProcessor` (SkiaSharp).
- Onboarding is **derived** from data on every request: profile complete (names, bio, mode, country, ≥ 1 language, photo), subjects chosen; offer and public-site steps are listed but not available until R1-P2–P4.
- SPA: `/app/w/{id}/profile` (photo, personal, teaching, location/currency), checklist on the dashboard (`src/app/pages/profile`), data hooks in `src/teacher/queries.ts`.

## Auth UI and session (R0-P7)

- Screens (`src/app/pages/auth`): sign in, register, verify email, forgot and reset password, with React Hook Form + Zod (`src/auth/schemas.ts` mirrors the API rules; the API stays authoritative). Field errors from the API are shown as translated messages, never as server text.
- Session (`src/auth/session.ts`): `useMe()` (`GET /api/auth/me`, `null` on 401), sign-in/sign-out mutations that clear the query cache, and the account language: after sign-in the account's language wins; switching language while signed in saves it with `PATCH /api/auth/me` (`locale`, `timeZone`).
- `RequireAuth` guards `/app`, `/student` and `/admin` (UX only) and sends visitors to `/login?returnTo=…`; `safeReturnTo` accepts only same-site paths (no open redirect).
- Teacher area: `/app` opens `/app/w/{workspaceId}`; a workspace the user is not a member of shows "not found" (the API answers 404). The header shows the account and sign-out; unconfirmed accounts see a banner with "send again".
- Tokens from email links are read from the URL fragment once and removed from the address bar.
- OpenAPI: `RouteParameterOperationTransformer` documents route parameters that handlers do not bind (workspace routes), so the generated client can fill them.



`OpenApiContractTests` requires `web/src/api/openapi.json` to equal the API's `/openapi/v1.json` (server URLs removed). `npm run api:types` generates `web/src/api/schema.d.ts` from it; CI fails if either is stale. Update flow after an API change:

```powershell
$env:CLASSHUB_UPDATE_OPENAPI='1'; dotnet test --project tests/ClassHub.IntegrationTests -- --filter-class "*OpenApiContractTests"; Remove-Item Env:CLASSHUB_UPDATE_OPENAPI
cd web; npm run api:types
```

## Principles (from ROADMAP)

- **Modular monolith:** `ClassHub.Api` is only the composition root. Business modules live in `ClassHub.Core/Modules/<Name>/` and implement `IModule`. A module may use another module only through its `Contracts` namespace (enforced by architecture tests from R0-P3).
- **Single origin:** `/api/*` (REST), SPA routes (`/app`, `/student`, `/admin`, auth pages) and Razor public pages (`/`, `/{slug}`, …) are all served by one ASP.NET Core app (from R0-P6 / R1-P4).
- **Tenant isolation:** each teacher's workspace is the tenant boundary; layered isolation per ROADMAP C.7 (from R0-P5).
- **Contracts:** the OpenAPI document is generated at build time and turned into TypeScript types for the SPA (from R0-P3).

## Toolchain decisions taken during implementation

| Topic | Decision | Reason |
|---|---|---|
| Test runner | Microsoft.Testing.Platform (opt-in in `global.json`); no `Microsoft.NET.Test.Sdk`/VSTest adapter | xunit.v3 4.x on the .NET 10 SDK no longer supports the VSTest target |
| Restore | Central package management + `packages.lock.json`, CI uses `--locked-mode` | Reproducible builds |
| Package source | `NuGet.config` clears sources and uses nuget.org only | No machine-specific feeds |
| Security pins | `CentralPackageTransitivePinningEnabled`; `System.Security.Cryptography.Pkcs` pinned to 10.0.14 | Microsoft.Data.SqlClient 6.1.7 brings Pkcs 9.0.11 (GHSA-846f-f764-76mx high, GHSA-2fmv-rv2c-59x7 moderate); NuGet audit warnings are build errors |
| Database collation | Applied by EF on database creation (`UseCollation`), no migration step | EF does not emit `AlterDatabase` for the initial model; verified by tests and the CI `migrations` job |
| Migrations | Excluded from style analyzers via `.editorconfig` (`generated_code = true`) | Generated code |
| Unknown routes | Anonymous → 401 (fallback policy), authenticated → 404 | Deny-by-default includes unmatched requests |
| openapi-typescript + TS 6 | npm `overrides` lets only `openapi-typescript` use the project's TypeScript 6.0 (its peer range is `^5.x`) | No release supports TS 6 yet; narrower than `--legacy-peer-deps`. Generation and type-check verified |
| Dev-only audit findings | 3 moderate advisories in `openapi-typescript` → `@redocly/openapi-core` → `minimatch` (GHSA-g3hv-75wg-m249) accepted | Build-time tool, input is our own committed JSON, not shipped; the only fix is a breaking downgrade. Production `npm audit` is clean; re-check on each Dependabot update |
| Dependabot | TypeScript and `@types/node` major updates ignored | D-04 (TS 6.0) and the Node 22 runtime |
